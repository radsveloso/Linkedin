Qlik Predict Agent: o que o AutoML com IA significa para quem já une Python e Qlik

Em junho de 2026, o Qlik lançou o Predict Agent: um agente de IA que conduz o ciclo completo de machine learning dentro do Qlik Cloud, com SHAP individual por registro e aprendizado contínuo. A pergunta que nenhum artigo em PT-BR respondeu ainda: quando isso substitui seu pipeline Python e quando definitivamente não substitui.

Não é só AutoML rebatizado

O Qlik Predict existe desde a fase chamada Qlik AutoML. O que mudou em junho de 2026 foi a adição de uma camada de agente de IA sobre esse motor. A diferença prática é relevante para quem já usou o AutoML anterior.

Com o AutoML puro, você configurava um experimento manualmente: escolhia a variável-alvo, selecionava as features, iniciava o treinamento e interpretava os gráficos de resultado. Era mais rápido que código, mas ainda exigia que você soubesse o que estava pedindo e entendesse os resultados.

Com o Predict Agent, você faz uma pergunta em linguagem natural: "Quais clientes têm maior probabilidade de cancelar nos próximos 30 dias?" O agente entende o problema, identifica as features relevantes, treina múltiplos modelos, compara a acurácia entre eles, gera as previsões e explica os resultados com visualizações de SHAP. O ciclo completo acontece dentro de uma conversa.

Ponto técnico
O motor de ML subjacente não mudou. O que o agente adiciona é: (1) tradução de perguntas em linguagem natural para configurações de experimento, (2) decisões automáticas sobre seleção de features e tipo de problema de ML, (3) narrativa de interpretação dos resultados sem exigir que o usuário leia um gráfico de SHAP sozinho.

O ciclo de ML que o agente conduz

O Predict Agent cobre seis etapas do ciclo de data science sem exigir configuração manual em cada uma. Para o dev sênior, isso significa que o boilerplate de ML, antes seu, migra para o agente.

01 Entender o problema
02 Preparar os dados
03 Construir modelos
04 Validar resultados
05 Gerar previsões
06 Interpretar com IA

O que está disponível em GA

Previsão de séries temporais multivariada com suporte a sazonalidade e dependências complexas entre variáveis. SHAP values a nível de registro individual: não só "quais features importam para o modelo geral", mas "por que este cliente específico recebeu este score". Aprendizado contínuo, onde os modelos se atualizam automaticamente à medida que novos dados chegam. Governança com documentação embutida, logs de auditoria e rastreamento do ciclo de vida do modelo.

SHAP individual: o que muda na prática
A maioria das ferramentas de AutoML mostra importância de feature global, ou seja, "recência de compra contribui 28% para o modelo". O Predict Agent mostra por que aquele registro específico recebeu aquele score. Para um analista apresentar a previsão de churn para o gerente de conta, isso muda a conversa: de "o modelo diz que a probabilidade é 87%" para "este cliente está em risco porque o volume de pedidos caiu 40% nos últimos 60 dias e o ticket médio ficou 35% abaixo do histórico dele". O stakeholder entende sem precisar de treinamento em ML.

Predict Agent vs. Python externo: quando usar cada um

Esta é a decisão que mais vai impactar devs sênior que já têm pipelines de ML fora do Qlik. A resposta honesta: depende do cenário. Os dois coexistem e não há razão para migrar tudo para o agente só porque ele existe.

Regra prática
Se o dado já está no Qlik, o problema é classificação ou regressão padrão e o resultado precisa aparecer no app para o usuário de negócio, o Predict Agent chega lá mais rápido. Se o problema exige feature engineering pesada, integração com dados fora do Qlik, ou controle granular do artefato de modelo, Python externo ainda é a escolha certa.

Como funciona na prática: de pergunta a previsão no app

Um exemplo concreto com dados de varejo. Você tem CustomersFact e OrdersFact no seu Data Product no Qlik Cloud. Abre o Predict Agent e descreve o que precisa: 

-- Prompt para o Predict Agent
"Usando os dados de CustomersFact e OrdersFact, quero prever
 quais clientes têm mais de 70% de probabilidade de não fazer
 nenhuma compra nos próximos 60 dias.

 Inclua uma explicação de por que cada cliente está em risco,
 usando as variáveis disponíveis nos dados."

O agente executa a sequência completa de forma autônoma:

1. Entendimento do problema: classifica como problema de classificação binária (churn nos próximos 60 dias: sim ou não). Define a variável-alvo e o horizonte de previsão com base na descrição.

2. Seleção de features: analisa as colunas disponíveis e sugere as mais relevantes: recência da última compra, frequência de pedidos nos últimos 90 dias, variação do ticket médio, número de categorias compradas, tempo como cliente ativo.

3. Treinamento e validação: treina múltiplos algoritmos, compara AUC-ROC e F1-score entre eles, seleciona o modelo com melhor desempenho de validação e apresenta as métricas para revisão.

4. Geração de previsões: aplica o modelo a todos os clientes ativos e gera um score de probabilidade de churn por registro.

5. Explicação individual com SHAP: para cada cliente acima do limiar de 70% de probabilidade, gera SHAP values individuais com a contribuição positiva ou negativa de cada feature no score daquele registro específico.

O resultado final aparece como uma tabela no seu app Qlik com o score por cliente, acompanhada de um gráfico de SHAP que o gerente de conta consegue interpretar sem precisar de treinamento em machine learning.

O que antes levava semanas
Esse fluxo, feito com Python externo e integração manual no Qlik, levava entre duas e quatro semanas de engenharia: coleta de dados, pipeline de feature engineering, treinamento, versionamento do modelo, API de inferência, conector no Qlik e agendamento de atualização. Com o Predict Agent, a entrega vai para a tarde do mesmo dia, desde que os dados já estejam no Data Product com a qualidade necessária.

O combo que ninguém está falando: Predict + Automate Agent

O Qlik lançou o Automate Agent na mesma janela de junho de 2026. Quando combinado com o Predict Agent, ele fecha um loop que antes exigia múltiplos sistemas externos e integração manual entre eles.

Predict Agent

Detecta e prevê: identifica clientes em risco, prevê queda de margem, antecipa gargalo de supply chain. Retorna score com explicação individual por registro.

GA Jun 2026

Automate Agent

Age sobre a previsão: usa o resultado do Predict Agent para disparar ações em sistemas externos via linguagem natural. CRM, ERP, sistemas de procurement, plataformas de comunicação.

GA Jun 2026

Analytics Agent

Investiga causas: responde perguntas analíticas sobre os dados, explora variações e apoia tanto a geração de insights quanto o desenvolvimento de analytics no Qlik Cloud.

Previsto Q3 2026

O exemplo que o próprio Qlik usa é de supply chain: o Predict Agent identifica 82% de probabilidade de ruptura de estoque em uma SKU crítica nos próximos 14 dias. O Automate Agent, sem intervenção humana, abre automaticamente um workflow de procurement no sistema de compras para identificar fornecedor alternativo.

Para times de BI que hoje entregam dashboards de monitoramento, isso representa uma mudança de paradigma: de "o dashboard avisa que há um problema" para "o sistema age sobre o problema antes que ele apareça no relatório de manhã".

Para o dev sênior: o que isso muda no design do sistema
Se você está construindo um app Qlik que serve como painel de monitoramento de KPIs, vale mapear quais KPIs têm uma ação associada quando ficam fora do threshold esperado. Esses são os candidatos naturais ao loop Predict + Automate. A lógica da ação sai do seu pipeline manual e vai para o agente, mas o contrato de dados que alimenta o modelo continua sendo responsabilidade do engenheiro.

O que fica na mão do dev sênior

O Predict Agent não elimina a responsabilidade técnica do engenheiro. Ele a desloca. Entender exatamente o que migra para o agente e o que permanece com você é o que separa a adoção bem-sucedida do retrabalho.

O agente assume

  • Seleção automática de algoritmos
  • Tuning de hiperparâmetros
  • Validação cruzada e seleção do melhor modelo
  • SHAP values e narrativa de explicação
  • Atualização automática do modelo com novos dados
  • Documentação e log de auditoria do experimento
  • Integração do resultado no app Qlik

Você continua responsável

  • Qualidade e granularidade dos dados no Data Product
  • Feature engineering específica de domínio
  • Definição correta do problema e da variável-alvo
  • Modelos com requisitos regulatórios rígidos
  • Arquiteturas de ML além de classificação e regressão
  • Integração com fontes de dados fora do Qlik
  • Governança de acesso aos resultados via Section Access

O ponto crítico que o marketing não menciona: o Predict Agent é tão bom quanto os dados que chegam até ele. Se o Data Product de entrada tem problemas de qualidade, latência alta ou granularidade insuficiente, o agente vai gerar um modelo tecnicamente válido mas praticamente inútil para o negócio. A responsabilidade sobre a camada de dados continua sendo do engenheiro, e as semanas economizadas na parte de ML podem ser consumidas inteiramente por dívida técnica na camada de ingestão e transformação.
