A arquitetura

Os 5 pilares técnicos

Cada artigo da série é construído sobre os mesmos 5 pilares. O que muda é a paleta de cores e o conteúdo. A estrutura é sempre esta.

1
Canvas Particle Animation
60 partículas com cores temáticas, velocidade aleatória e linhas de conexão quando a distância é menor que 110px. Cria a sensação de profundidade sem pesar a página. Desenhado em requestAnimationFrame para performance máxima.
2
IntersectionObserver para Scroll
Todos os elementos com classe .fade-up ganham animacao de entrada quando entram no viewport. Zero bibliotecas de scroll. O mesmo observer atualiza os nav dots ativos conforme o usuário navega.
3
Nav Dots com Labels no Hover
Navegacao lateral fixa com um ponto por seção. Hover revela o nome da seção via CSS ::after. Clique executa scrollIntoView com behavior smooth. Ativo rastreado via IntersectionObserver das seções.
4
Paleta Temática via CSS Variables
Cada artigo tem uma identidade visual própria definida em :root. Semana 2 usou vermelho para erros. Semana 3 usou dourado para carreira. Semana 4 usa violeta para meta/processo. Trocar a paleta leva menos de 2 minutos.
5
Zero Dependências Externas
Nenhum CDN, nenhum framework, nenhum import externo. HTML, CSS e JavaScript puros. O arquivo abre em qualquer browser, em qualquer conexão, em qualquer dispositivo. E nunca vai quebrar porque uma biblioteca saiu de manutenção.
Debaixo do capô

O sistema de partículas

Este é o núcleo do canvas. A lógica é simples: cada partícula tem posição, velocidade e cor. O loop desenha partículas, depois verifica distâncias e desenha as linhas.

canvas-particles.js 
// Classe Particle - cor temática via RGB
class Particle {
  constructor(w, h) {
    this.x = Math.random() * w;
    this.y = Math.random() * h;
    this.vx = (Math.random() - 0.5) * 0.6;
    this.vy = (Math.random() - 0.5) * 0.6;
    this.r  = Math.random() * 1.8 + 0.6;
    // Troque os valores RGB para mudar a paleta:
    this.color = Math.random() > .5
      ? '139,92,246'   // violet
      : '6,182,212';   // cyan
  }
  update(w, h) {
    this.x += this.vx;
    this.y += this.vy;
    if (this.x < 0 || this.x > w) this.vx *= -1;
    if (this.y < 0 || this.y > h) this.vy *= -1;
  }
}

function animate() {
  ctx.clearRect(0, 0, W, H);
  particles.forEach(p => p.update(W, H));

  // Desenha linhas de conexão
  for (let i = 0; i < particles.length; i++) {
    for (let j = i + 1; j < particles.length; j++) {
      const dx = particles[i].x - particles[j].x;
      const dy = particles[i].y - particles[j].y;
      const dist = Math.sqrt(dx*dx + dy*dy);
      if (dist < 110) {
        ctx.strokeStyle = `rgba(139,92,246,${(1-dist/110)*.18})`;
        ctx.beginPath();
        ctx.moveTo(particles[i].x, particles[i].y);
        ctx.lineTo(particles[j].x, particles[j].y);
        ctx.stroke();
      }
    }
  }
  particles.forEach(p => {
    ctx.beginPath();
    ctx.arc(p.x, p.y, p.r, 0, Math.PI*2);
    ctx.fillStyle = `rgba(${p.color},0.7)`;
    ctx.fill();
  });
  requestAnimationFrame(animate);
}

Nao é um prompt de uma linha. É uma especificação técnica estruturada que define visual, arquitetura e conteúdo de uma vez. Aqui está a estrutura que uso para cada artigo.

🤖
Estrutura do Prompt de Geração
Template base - adapte para cada artigo
1. Papel e Contexto
Você está criando um artigo HTML single-file premium para publicar no LinkedIn via GitHub Pages. O artigo deve ser completamente self-contained: zero dependências externas, zero CDNs. Dark theme profissional. Público: desenvolvedores Qlik Cloud sênior.
2. Especificação Visual
- Canvas com 60 partículas animadas nas cores [COR1] e [COR2] - IntersectionObserver para fade-up no scroll de todos os .fade-up - Nav dots laterais fixos com data-label e hover tooltip via CSS ::after - Hero badge com pulsing dot animado - CSS Variables em :root para toda a paleta - Mobile responsive (grid muda em <600px)

Seção 0: Hero - badge + h1 + subtítulo + 4 stat cards Seção 1: Problema - por que o tema importa Seção 2: Conceito central - 3 a 5 blocos com ícone Seção 3: Técnica profunda - code block com syntax highlight inline Seção 4: Análise comparativa - antes/depois ou comparação Seção 5: Insight avançado - o que a maioria nao sabe Seção 6: Aplicacao prática - passo a passo Seção 7: CTA - frase de impacto + hashtags

- ZERO em dashes (—) em todo o arquivo - PT-BR com acentuação completa em todas as palavras - Nenhum link externo (imagens, fontes, scripts) - Sem frameworks: HTML/CSS/JS puro - Arquivo deve abrir offline sem erros

O segredo nao está no prompt em si. Está em iterar sobre o template. Cada artigo publicado ensina algo novo sobre o que funciona visualmente para o público técnico do LinkedIn. A versão atual é resultado de 4 rodadas de refinamento.

Do zero ao LinkedIn

O processo completo

Do tema ao artigo publicado, o processo leva menos de 2 horas quando o template está pronto. A maior parte do tempo está na revisão do conteúdo técnico, nao na geração.

💡
1. Escolha do Tema
Tema técnico que eu mesmo já enfrentei no trabalho. Preferência por dores que nao tem boa documentacao em PT-BR no LinkedIn.
🎨
2. Definição da Paleta
Escolho a cor baseado no tom do artigo. Erros? Vermelho. Oportunidade? Dourado. Bastidores? Violeta.
🤖
3. Geração via IA
Uso o prompt estruturado com Claude para gerar o HTML completo. Especifico paleta, seções e conteúdo técnico.
🔍
4. Revisão Técnica
Verifico todos os snippets de código, textos em PT-BR com acentos corretos, e ausência de em dashes.
🚀
5. Push para GitHub Pages
Um único comando gh api PUT envia o arquivo. Em 2 minutos está online com URL permanente.
📢
6. Post no LinkedIn
Post de acompanhamento com gancho forte, link para o artigo e hashtags estratégicas. Nao publico o HTML diretamente no editor do LinkedIn.
