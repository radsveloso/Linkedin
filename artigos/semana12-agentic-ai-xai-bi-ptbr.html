O BI que age e o BI que explica:
Agentic AI + XAI na prática

Como a combinação de agentes autônomos e inteligência explicável está redefinindo o trabalho do analista de dados em 2026

por Rafael Veloso Agosto 2026 Leitura: ~8 min

"Um dashboard que você precisa abrir para descobrir um problema já está atrasado. Um agente que te avisa - e explica por que - é o futuro do BI."

Em 2026, duas tendências dominam as conversas sobre inteligência artificial aplicada a dados: Agentic AI (sistemas que agem de forma autônoma) e Explainable AI / XAI (sistemas que justificam suas decisões). Separadas, cada uma já tem valor. Juntas, elas resolvem o maior problema histórico do BI corporativo: velocidade sem sacrificar confiança.

Neste artigo, vou mostrar o que cada abordagem significa na prática, com exemplos reais de código, arquiteturas e casos de uso em ferramentas como Qlik, Power BI e Python.

Parte 1: Agentic AI em BI

Agentic AI não é simplesmente um copilot que responde perguntas. É um sistema que percebe o ambiente, toma decisões e executa ações de forma autônoma - sem precisar que um humano formule cada consulta.

O que muda na prática?

BI Tradicional

Analista abre o dashboard toda manha, verifica KPIs, percebe que vendas caiu 12%, investiga manualmente, descobre a causa horas depois, gera relatorio e envia para o gestor.

BI com Agentic AI

Agente monitora KPIs continuamente, detecta queda de 12% em vendas às 02:17, identifica automaticamente a causa (falha logística no região Sul), cria sumário e notifica o gestor antes dàs 07:00.

Arquitetura de um Agente de BI Autonomo

-- Fluxo de um Agente de BI Autonomo -- [FONTES DE DADOS] Qlik Cloud / Power BI Dataset / Data Warehouse | v [CAMADA DE PERCEPCAO] Agente monitora KPIs via API ou webhook Threshold dinâmico (media movel + desvio padrao) | v [MOTOR DE DECISAO] [MEMORIA CONTEXTUAL] Analisa anomalia <--- Histórico de incidentes Prioriza severidade Sazonalidade conhecida Seleciona ação Regras de negócio | v [CAMADA DE EXECUCAO] - Roda query de investigação - Correlaciona com outras métricas - Gera narrativa explicativa | v [OUTPUT] Alerta + Contexto + Acao Sugerida -> Slack / Email / Teams

Exemplo prático: Agente de monitoramento com Python

Abaixo, um exemplo funcional de como implementar um agente simples que monitora uma métrica via API do Qlik e dispara alertas com contexto:

Python - Agente de Monitoramento
import requests
import statistics
from datetime import datetime, timedelta

class BIAgent:
    def __init__(self, qlik_api_url, auth_token, slack_webhook):
        self.api_url = qlik_api_url
        self.headers = {"Authorization": f"Bearer {auth_token}"}
        self.slack_webhook = slack_webhook
        self.memory = {}  # Histórico de métricas

    def fetch_kpi(self, metric_name: str, days_back: int = 30) -> list:
        """Busca histórico de um KPI via Qlik REST API"""
        end_date = datetime.now()
        start_date = end_date - timedelta(days=days_back)

        response = requests.get(
            f"{self.api_url}/metrics/{metric_name}",
            headers=self.headers,
            params={
                "startDate": start_date.isoformat(),
                "endDate": end_date.isoformat()
            }
        )
        return response.json()["values"]

    def detect_anomaly(self, values: list, sensitivity: float = 2.0) -> dict:
        """Detecta anomalias usando z-score dinâmico"""
        if len(values) < 7:
            return {"is_anomaly": False}

        recent = values[-1]           # Valor atual
        baseline = values[:-1]        # Histórico

        mean = statistics.mean(baseline)
        stdev = statistics.stdev(baseline)

        if stdev == 0:
            return {"is_anomaly": False}

        z_score = (recent - mean) / stdev
        pct_change = ((recent - mean) / mean) * 100

        return {
            "is_anomaly": abs(z_score) > sensitivity,
            "direction": "queda" if recent < mean else "alta",
            "z_score": round(z_score, 2),
            "pct_change": round(pct_change, 1),
            "current_value": recent,
            "expected_value": round(mean, 2)
        }

    def investigate(self, metric_name: str, anomaly: dict) -> str:
        """Investiga causa raiz da anomalia correlacionando métricas"""
        # Busca métricas correlacionadas
        correlations = []
        related_metrics = ["conversão", "tráfego", "estoque", "logística"]

        for related in related_metrics:
            values = self.fetch_kpi(related, days_back=7)
            if values:
                delta = ((values[-1] - values[-2]) / values[-2]) * 100
                if abs(delta) > 5:  # Mudanca significativa
                    correlations.append(f"{related}: {delta:+.1f}%")

        context = f"""
Anomalia detectada em {metric_name}:
- Variação: {anomaly['pct_change']:+.1f}% ({anomaly['direction']})
- Z-score: {anomaly['z_score']} (sensibilidade: 2.0 sigma)
- Valor atual: {anomaly['current_value']}
- Valor esperado: {anomaly['expected_value']}

Métricas correlacionadas com variação significativa:
{chr(10).join(correlations) if correlations else "Nenhuma correlação significativa encontrada"}
        """
        return context.strip()

    def alert(self, metric_name: str, investigation: str):
        """Envia alerta estruturado para o Slack"""
        payload = {
            "text": f":rotating_light: *Anomalia detectada: {metric_name}*",
            "blocks": [
                {
                    "type": "section",
                    "text": {
                        "type": "mrkdwn",
                        "text": f"*Agente BI detectou anomalia*\n```{investigation}```"
                    }
                }
            ]
        }
        requests.post(self.slack_webhook, json=payload)

    def run(self, metrics_to_monitor: list):
        """Loop principal do agente"""
        for metric in metrics_to_monitor:
            values = self.fetch_kpi(metric)
            anomaly = self.detect_anomaly(values)

            if anomaly["is_anomaly"]:
                investigation = self.investigate(metric, anomaly)
                self.alert(metric, investigation)
                print(f"[{datetime.now()}] Alerta enviado para {metric}")

Se você já configurou o Qlik MCP Server (veja o artigo da Semana 11), pode usar o Claude como motor de raciocínio do agente diretamente:

Exemplo - Qlik MCP + Claude como Agente
# O agente usa o Qlik MCP para acessar dados do Qlik Cloud
# e o Claude API para gerar o raciocínio e narrativa

import anthropic

client = anthropic.Anthropic()

def analyze_with_claude(metric_data: dict) -> str:
    """Usa Claude para analisar anomalia e gerar explicação"""

    prompt = f"""
    Você e um agente de BI. Analise os dados abaixo e:
    1. Identifique se ha anomalia
    2. Sugira as 3 causas mais provaveis em ordem de probabilidade
    3. Recomende uma ação imediata
    4. Estime o impacto financeiro se não tratado

    Dados do Qlik Cloud:
    {metric_data}

    Responda de forma direta e estruturada para um gestor de negócios.
    """

    response = client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=500,
        messages=[{"role": "user", "content": prompt}]
    )

    return response.content[0].text

Parte 2: Explainable AI (XAI) - O BI que presta contas

Agentic AI resolve a velocidade. XAI resolve a confiança. Sem explicabilidade, um agente autônomo é uma caixa preta - e nenhum gestor sério vai confiar em decisões que não consegue auditar.

XAI não é sobre mostrar código ou logs técnico. É sobre responder: "Por que o sistema chegou nessa conclusão?" em linguagem que qualquer stakeholder entenda.

Os 3 níveis de explicabilidade em BI

Nível O que explica Para quem Exemplo
Global Como o modelo funciona em geral Equipe de dados Feature importance geral do modelo preditivo
Local Por que esta predição específica foi feita Analista / Gestor "Esta venda foi classif. como churn porque NPS < 6 e inatividade > 45 dias"
Contrafactual O que mudaria para um resultado diferente Time de negócios "Se o NPS fosse 7+, a probabilidade de churn cairia para 18%"

XAI na prática: SHAP com dados de BI

SHAP (SHapley Additive exPlanations) é a técnica mais adotada para explicabilidade em modelos de ML. Veja como usar com dados de BI:

Python - SHAP para explicar predições de Churn
import shap
import pandas as pd
import numpy as np
from sklearn.ensemble import GradientBoostingClassifier
import matplotlib.pyplot as plt

# Dados de clientes (simulado - equivalente ao que viria do Qlik/Power BI)
df = pd.DataFrame({
    'nps_score':         [8, 3, 7, 2, 9, 4, 6, 1],
    'dias_inativo':      [5, 60, 10, 75, 3, 45, 20, 90],
    'tickets_abertos':   [0, 5,  1,  8,  0,  3,  1, 10],
    'uso_features_pct':  [85, 20, 70, 10, 95, 35, 60, 5],
    'valor_contrato':    [5000, 800, 3200, 400, 8000, 1200, 2500, 300],
    'churn':             [0, 1, 0, 1, 0, 1, 0, 1]
})

X = df.drop('churn', axis=1)
y = df['churn']

# Treina modelo (simplificado para demonstração)
model = GradientBoostingClassifier(n_estimators=100, random_state=42)
model.fit(X, y)

# Cria o explainer SHAP
explainer = shap.TreeExplainer(model)
shap_values = explainer.shap_values(X)

# --- EXPLICACAO GLOBAL (feature importance) ---
print("=== Importância Global das Variaveis ===")
feature_importance = pd.DataFrame({
    'feature': X.columns,
    'importance': np.abs(shap_values).mean(axis=0)
}).sort_values('importance', ascending=False)
print(feature_importance.to_string(index=False))

# Output esperado:
#           feature  importance
#       dias_inativo    0.3821
#          nps_score    0.2945
#   uso_features_pct    0.1823
#    tickets_abertos    0.1234
#    valor_contrato     0.0177

# --- EXPLICACAO LOCAL (por cliente específico) ---
def explain_prediction(client_idx: int, df: pd.DataFrame,
                        shap_values, threshold: float = 0.5) -> str:
    """Gera explicação legivel para um cliente específico"""
    prediction_prob = model.predict_proba(X.iloc[[client_idx]])[0][1]
    prediction = "CHURN" if prediction_prob >= threshold else "ATIVO"

    client_shap = shap_values[client_idx]
    feature_impact = sorted(
        zip(X.columns, client_shap),
        key=lambda x: abs(x[1]),
        reverse=True
    )

    explanation = f"""
[Cliente #{client_idx}] Predição: {prediction} ({prediction_prob:.0%} prob. churn)

Fatores determinantes:
"""
    for feat, impact in feature_impact:
        direction = "aumentou" if impact > 0 else "reduziu"
        val = df.iloc[client_idx][feat]
        explanation += f"  - {feat} = {val} -> {direction} risco ({impact:+.3f})\n"

    # Analise contrafactual simples
    if prediction == "CHURN":
        explanation += "\nPara reduzir risco: aumentar NPS e reduzir dias de inatividade teriam maior impacto."

    return explanation.strip()

# Teste para cliente em risco (indice 1)
print(explain_prediction(1, df, shap_values))

# Output esperado:
# [Cliente #1] Predição: CHURN (89% prob. churn)
# Fatores determinantes:
#   - dias_inativo = 60 -> aumentou risco (+0.412)
#   - nps_score = 3 -> aumentou risco (+0.318)
#   - uso_features_pct = 20 -> aumentou risco (+0.195)
#   - tickets_abertos = 5 -> aumentou risco (+0.143)
#   - valor_contrato = 800 -> reduziu risco (-0.028)
# Para reduzir risco: aumentar NPS e reduzir dias de inatividade teriam maior impacto.

XAI no contexto do Qlik e Power BI

Qlik AutoML + XAI

O Qlik AutoML (Qlik Cloud) já inclui SHAP nativo nos modelos gerados. Você ve feature importance e pode exportar as explicações como campos calculados para usar em visualizações.

Power BI + Azure ML

Integração via Azure Machine Learning permite trazer explicações SHAP como colunas de uma tabela no Power BI. DAX pode entao formatar essas explicações em tooltips e narrativas.

A combinação: Agentic AI + XAI juntos

O verdadeiro poder emerge quando o agente autônomo é obrigado a justificar cada ação que toma. Veja o fluxo completo:

1

Percepcao autônoma

Agente detecta queda de 18% nas vendas da região Sul às 03:42

2

Investigação correlacionada

Cruza com logística (-23%), clima (chuva intensa), histórico de datas similares e NPS regional

3

Explicação gerada automaticamente

XAI calcula contribuição de cada fator: logística (47%), clima (31%), sazonalidade (14%), outros (8%)

4

Acao + Narrativa

Agente notifica o gestor com: causa identificada, impacto estimado (R$ 42k), ação sugerida e confiança da análise (87%)

5

Feedback loop

Gestor confirma ou refuta a causa. Agente aprende e ajusta o modelo para a próxima vez.

Conclusao

O BI de 2026 não é sobre construir paineis mais bonitos. É sobre construir sistemas que percebem, agem e explicam - enquanto o analista foca em validar, refinar e decidir estrategicamente com base nisso.

Agentic AI sem XAI é perigoso: você não sabe por que o sistema fez o que fez. XAI sem Agentic AI é lento: você tem as explicações mas precisa fazer as perguntas certas. Juntos, eles formam o stack de BI mais poderoso disponível hoje.

  • Comece configurando alertas inteligentes com z-score dinâmico - não thresholds fixos
  • Adicione SHAP ao seu modelo preditivo mais crítico e mostre as explicações no dashboard
  • Experimente o Qlik MCP ou a API do Claude para adicionar raciocínio ao seu pipeline
  • Documente cada decisão autônoma do agente para auditoria - XAI torna isso viavel
