The architecture

The 5 technical pillars

Every article in the series is built on the same 5 pillars. What changes is the color palette and the content. The structure is always this.

1
Canvas Particle Animation
60 particles with theme colors, randomized velocity, and connection lines when distance is less than 110px. Creates a sense of depth without slowing down the page. Rendered in requestAnimationFrame for maximum performance.
2
IntersectionObserver for Scroll
Every element with class .fade-up gets an entrance animation when it enters the viewport. Zero scroll libraries needed. The same observer updates the active nav dot as the user navigates down the page.
3
Nav Dots with Hover Labels
Fixed side navigation with one dot per section. Hover reveals the section name via CSS ::after. Click calls scrollIntoView with smooth behavior. Active state tracked via IntersectionObserver on the sections themselves.
4
Thematic Palette via CSS Variables
Each article has its own visual identity defined in :root. Week 2 used red for errors. Week 3 used gold for career. Week 4 uses violet for meta and process. Swapping the palette takes less than 2 minutes.
5
Zero External Dependencies
No CDNs, no frameworks, no external imports. Pure HTML, CSS, and JavaScript. The file opens in any browser, on any connection, on any device. And it will never break because a library went unmaintained.
Under the hood

The particle system

This is the canvas core. The logic is simple: each particle has position, velocity, and color. The loop draws particles, then checks distances and draws the connection lines.

canvas-particles.js 
// Particle class - theme color via RGB string
class Particle {
  constructor(w, h) {
    this.x = Math.random() * w;
    this.y = Math.random() * h;
    this.vx = (Math.random() - 0.5) * 0.6;
    this.vy = (Math.random() - 0.5) * 0.6;
    this.r  = Math.random() * 1.8 + 0.6;
    // Change the RGB values to swap the palette:
    this.color = Math.random() > .5
      ? '139,92,246'   // violet
      : '6,182,212';   // cyan
  }
  update(w, h) {
    this.x += this.vx;
    this.y += this.vy;
    if (this.x < 0 || this.x > w) this.vx *= -1;
    if (this.y < 0 || this.y > h) this.vy *= -1;
  }
}

function animate() {
  ctx.clearRect(0, 0, W, H);
  particles.forEach(p => p.update(W, H));

  // Draw connection lines between close particles
  for (let i = 0; i < particles.length; i++) {
    for (let j = i + 1; j < particles.length; j++) {
      const dx = particles[i].x - particles[j].x;
      const dy = particles[i].y - particles[j].y;
      const dist = Math.sqrt(dx*dx + dy*dy);
      if (dist < 110) {
        ctx.strokeStyle = `rgba(139,92,246,${(1-dist/110)*.18})`;
        ctx.beginPath();
        ctx.moveTo(particles[i].x, particles[i].y);
        ctx.lineTo(particles[j].x, particles[j].y);
        ctx.stroke();
      }
    }
  }
  particles.forEach(p => {
    ctx.beginPath();
    ctx.arc(p.x, p.y, p.r, 0, Math.PI*2);
    ctx.fillStyle = `rgba(${p.color},0.7)`;
    ctx.fill();
  });
  requestAnimationFrame(animate);
}
The method

The prompt I use with AI

It is not a one-line prompt. It is a structured technical specification that defines visual design, architecture, and content all at once. Here is the structure I use for every article.

🤖
Generation Prompt Structure
Base template - adapt for each article
1. Role and Context
You are creating a premium single-file HTML article to publish on LinkedIn via GitHub Pages. The article must be fully self-contained: zero external dependencies, zero CDNs. Professional dark theme. Audience: senior Qlik Cloud developers.
2. Visual Specification
- Canvas with 60 animated particles in colors [COLOR1] and [COLOR2] - IntersectionObserver for fade-up on scroll of all .fade-up elements - Fixed side nav dots with data-label and hover tooltip via CSS ::after - Hero badge with animated pulsing dot - CSS Variables in :root for the entire palette - Mobile responsive (grid changes at <600px)
3. Thematic Palette
--primary: [HEX] /* main accent color */ --primary2: [HEX] /* lighter variation */ --bg: #07080e /* background fixed across all articles */ // Examples by theme: Errors/Bugs: red #ef4444 Career: gold #f59e0b Meta/Process: violet #8b5cf6 Cloud/Infra: blue #3b82f6 Performance: green #10b981
4. Section Structure (8 sections)
Section 0: Hero - badge + h1 + subtitle + 4 stat cards Section 1: Problem - why the topic matters Section 2: Core concept - 3 to 5 blocks with icons Section 3: Deep technical - code block with inline syntax highlight Section 4: Comparative analysis - before/after or comparison Section 5: Advanced insight - what most people don't know Section 6: Practical application - step by step Section 7: CTA - impact statement + hashtags
5. Non-Negotiable Rules
- ZERO em dashes (--) in the entire file - No external links (images, fonts, scripts) - No frameworks: pure HTML/CSS/JS - File must open offline without errors - All code examples must be real and functional

The secret is not the prompt itself. It is iteration on the template. Each published article teaches something new about what works visually for a technical audience on LinkedIn. The current version is the result of 4 rounds of refinement.

Zero to LinkedIn

The complete process

From topic to published article, the process takes less than 2 hours when the template is ready. Most of the time goes into reviewing the technical content, not the generation.

💡
1. Choose the Topic
A technical topic I have personally encountered at work. Preference for pain points with poor documentation in English on LinkedIn.
🎨
2. Define the Palette
I choose the color based on the article tone. Errors? Red. Opportunity? Gold. Behind the scenes? Violet.
🤖
3. Generate with AI
I use the structured prompt with Claude to generate the complete HTML. I specify palette, sections, and technical content.
🔍
4. Technical Review
I verify all code snippets, language accuracy, and confirm zero em dashes anywhere in the file.
🚀
5. Push to GitHub Pages
A single gh api PUT command uploads the file. Within 2 minutes it is live with a permanent URL.
📢
6. Post on LinkedIn
A companion post with a strong hook, link to the article, and strategic hashtags. I never publish the HTML directly in the LinkedIn editor.
