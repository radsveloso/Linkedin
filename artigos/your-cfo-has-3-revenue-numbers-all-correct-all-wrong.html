The Problem

The Meeting That Froze the Room

"Board meeting. The CFO asks: what was March revenue? Three Power BI dashboards open on the table. Three different numbers. Silence. Nobody knew which one was right."

This is not a bug. Not an ETL error. It is the natural outcome of an organization that grew without semantic model governance.

Every team built their own .pbix. Every analyst defined "Revenue" their own way. All definitions make sense within each team's context. And that is exactly the problem.

The Three Versions of the Same Number

Sales Team 
Revenue =
CALCULATE(
  SUM(Sales[Amount]),
  Sales[Status] = "Delivered"
)
Finance Team 
Revenue =
CALCULATE(
  SUM(Sales[Amount]),
  Sales[Status] IN
  {"Delivered","Invoiced"}
)
Operations Team (different table) 
Revenue = SUM(Invoices[TotalAmount])

Three measures. Same name. Three different source tables. Three different filters. All defensible. None reliable in isolation.

Diagnosis

5 Signs Your Company Has This Problem

  • ✗Reports with same-name metrics returning different numbers for the same period
  • ✗No certified or promoted datasets in Power BI Service
  • ✗Each analyst maintains their own local "master model" in .pbix
  • ✗No DAX measure naming convention across teams
  • ✗Data refreshes failing silently with no alerts or defined owners

If you checked 3 or more, your company does not have a Power BI problem. It has a data governance problem.

The Solution

Certified Semantic Model: One Source of Truth

The solution is not to ban teams from creating reports. It is to ensure all reports draw from the same source.

4-Layer Governance Architecture

1
Single Data Source (Data Lake / Warehouse) Bronze, Silver, Gold. One canonical Sales table, with business rules applied in the pipeline, not in the report.
2
Central Semantic Model (Certified) A single .pbix or Semantic Model in Fabric with ALL metrics defined, documented, and versioned.
3
Live Connection for Reports All teams connect via Live Connection. They create visualizations. They do not create measures. The semantic model is sovereign.
4
Endorsement + Defined Ownership Dataset certified in Power BI Service. Responsible owner. Refresh SLA. Active failure alerts.

The Central Model DAX

Certified Semantic Model — single source 
// Measures with clear names and documented definitions
[Delivered Revenue] =
    CALCULATE(
        SUM(Sales[Amount]),
        Sales[Status] = "Delivered"
    )

[Invoiced Revenue] =
    CALCULATE(
        SUM(Sales[Amount]),
        Sales[Status] = "Invoiced"
    )

// Canonical metric the CFO sees on the board
[Total Revenue] =
    [Delivered Revenue] + [Invoiced Revenue]

// Month-over-month change (standardized company-wide)
[Total Revenue MoM%] =
    DIVIDE(
        [Total Revenue] -
        CALCULATE([Total Revenue], PREVIOUSMONTH(Calendar[Date])),
        CALCULATE([Total Revenue], PREVIOUSMONTH(Calendar[Date])),
        BLANK()
    )

Advanced Insight

Microsoft Fabric Changes the Governance Game

With Microsoft Fabric, semantic model governance evolves to a level that traditional Power BI could not reach.

What changes with Fabric

  • ✓OneLake as single source: all data in one repository, no silos between teams
  • ✓Direct Lake mode: Import-level performance without the cost of replicating data, directly from Delta Lake
  • ✓Versioned semantic models: native version control in Fabric Workspace
  • ✓Metrics Hub: central layer for business metrics with lineage traceability

Fabric does not automatically solve the governance problem. It provides the tools. The discipline of using a central semantic model is still an organizational decision, not a tool decision.
