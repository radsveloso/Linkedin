Seção 01 - O Ponto de Partida

Qlik é poderoso. Mas tem lacunas reais.

Todo time que sai do básico do Qlik Cloud encontra os mesmos limites. Não por falta de qualidade da ferramenta - mas porque nenhuma plataforma de BI consegue antecipar 100% das necessidades de cada empresa.

O que o nativo entrega
  • Tabela reta com sort e export básico
  • Objetos desconectados de sistemas externos
  • Documentação fora do app (Confluence, Wiki)
  • Suporte reportado fora do contexto analítico
  • Toolbar fixa, sem customização
O que as extensões Qore resolvem
  • Tabela enterprise com paginação real, presets e freeze
  • Ticket ServiceNow criado dentro do Qlik, com contexto do app
  • Documentação viva embutida no próprio dashboard
  • Suite de insights com auto-discovery de KPIs e data model
  • Botões nativos injetados na toolbar do Qlik Cloud
💡
O que são extensões no Qlik Cloud? São visualizações personalizadas construídas em JavaScript (RequireJS AMD) que rodam dentro do Qlik como objetos nativos - com acesso total ao QIX Engine, Engine API, propriedades do app e contexto de usuário. A diferença de um mashup: elas vivem dentro do app, não fora dele.
Seção 02 - Extensão 1
📊
Qore Straight Table
v1.0.34 · ~2.200 linhas de código · 9 arquivos
Paginação real via QIX Engine Presets de visualização Export CSV + PDF Alternate States Freeze de colunas

A tabela mais solicitada por analistas em qualquer empresa que usa Qlik. O nativo funciona - mas para dados reais em escala enterprise, não basta.

O problema que ela resolve

A Straight Table nativa do Qlik carrega dados com scroll infinito e paginação client-side - o que na prática significa que ao exportar, o usuário exporta o que está visível, não o dataset completo. Presets de visualização não existem. Freeze de coluna, idem.

Como a Qore Straight Table funciona

A diferença fundamental está na paginação via QIX Engine: em vez de carregar tudo e filtrar no client, a extensão envia chamadas qTop/qHeight direto para o Engine - respeitando o limite de 10.000 células por request e fazendo múltiplas chamadas quando necessário.

// Paginação real - nunca client-side row hiding
return ext.backendApi.getData([{
  qTop: top,
  qLeft: 0,
  qWidth: totalCols,
  qHeight: safeHeight  // floor(10000 / totalCols)
}]);
Para o Analista

Presets de visualização

Admin define visões pré-configuradas (colunas, filtros, ordenação, freeze). Usuário salva suas próprias visões por browser. Sem round-trip ao Engine para alternar.

Para o Desenvolvedor

applyPatches, não setProperties

Toda mutação usa applyPatches com qSoftPatch=false para evitar desincronização do qInterColumnSortOrder - bug que quebra outros objetos da sheet.

⚙️
Detalhe de engenharia: O Qlik Cloud bloqueia navigator.clipboard dentro de iframes. Copy/paste entre tabelas Qore usa localStorage como canal interno - transparente para o usuário, sem perda de funcionalidade.
Seção 03 - Extensão 2
📖
Qore Info Page
v2.28 · Singleton · Auto Discovery
Documentação embutida Auto-discovery de KPIs Data Model live Substitui Confluence/Wiki

Documentação de app que vive dentro do Qlik - não em uma wiki desatualizada que ninguém lê.

O problema que ela resolve

Em qualquer empresa com múltiplos apps Qlik, a documentação dos dashboards existe em algum Confluence ou SharePoint - desatualizada, difícil de encontrar, desconectada do contexto real do analista que está olhando para os dados agora.

Como funciona na prática

Ao adicionar a extensão em qualquer sheet, ela injeta um botão "About" na toolbar nativa do Qlik Cloud - ao lado do botão de Bookmarks, usando o mesmo design MUI. O clique abre um modal com abas configuráveis:

  • About - descrição do app em Markdown, com contatos responsáveis
  • KPIs - master measures destacadas com descrição e fórmula
  • Sheets - lista de todas as sheets publicadas do app
  • Data Model - tabelas e chaves lidas diretamente via enigma.getTablesAndKeys
  • Auto - tudo acima gerado automaticamente, sem o admin digitar nada
🔍
Auto Discovery em 4 chamadas paralelas: A aba Auto faz app.getList('sheet'), getList('MeasureList'), getList('DimensionList') e enigmaModel.getTablesAndKeys() simultaneamente - entregando um snapshot completo do app sem configuração manual.

Padrão Singleton

A extensão usa window.__qoreInfoPageInstance para garantir uma única instância por app - independente de quantas sheets contêm o objeto. Um setInterval de 2 segundos monitora se o botão "About" foi removido pela navegação do Qlik e o re-injeta automaticamente.

Seção 04 - Extensão 3
🎫
Qore Support Ticket
v3.54 · ServiceNow · Qlik Automation Webhook
ServiceNow integrado Contexto automático do app Lookups via Hypercube Smart Prefill

O analista encontrou um dado errado. Em vez de abrir outra aba, capturar prints e descrever o contexto do zero - ele abre um ticket direto do Qlik, com o contexto preenchido automaticamente.

O problema que ela resolve

Toda empresa que usa Qlik para dados críticos tem o mesmo problema: o analista encontra uma anomalia, não sabe se é dado errado ou regra de negócio, e o processo de reporte é lento e sem contexto. O resultado? Bugs que demoram semanas para serem corrigidos porque ninguém consegue reproduzi-los.

Arquitetura de integração

A extensão injeta um botão "Report Issue" na toolbar (mesmo padrão MUI da Info Page). O formulário usa o modelo de dados do próprio app para popular os dropdowns - sem endpoints externos, sem manutenção separada:

// Lookup de assignees direto do data model do app
cubeLookup.searchAsync(props.lookups.assignTo, query)
// → createSessionObject({qDimensions: [keyField, labelField]})
// → filtra por search term, retorna matching rows

O payload enviado ao ServiceNow via Qlik Automation inclui contexto automático - o analista não precisa descrever onde estava:

{
  "u_qlik_app": "app.id",
  "u_qlik_sheet": "sheet atual no momento do clique",
  "u_caller_email": "via getAuthenticatedUser()",
  "u_browser": "navigator.userAgent"
}
📈
Evolução em 4 versões: O lookup de dados passou de listas hard-coded (v3.22) para endpoints REST separados (v3.39) para um endpoint combinado (v3.40) até a versão atual com session hypercubes (v3.43) - eliminando qualquer serviço externo e usando o data model do Qlik diretamente.

Seção 06 - Para os Desenvolvedores

Padrões que tornam extensões enterprise-grade

O que separa uma extensão que funciona em demo de uma que sobrevive em produção com centenas de usuários simultâneos.

1. Padrão Singleton

Extensões globais (Info Page, Support Ticket) usam uma chave no window para garantir uma única instância, independente de quantas sheets contêm o objeto:

if (window['__qoreInfoPageInstance']) {
  window['__qoreInfoPageInstance'].layout = layout;
  return; // já inicializado - apenas atualiza estado
}
// Primeira chamada: bootstrap completo
window['__qoreInfoPageInstance'] = { layout, ctx, destroy };

2. Injeção de Toolbar (MUI Clone)

Em vez de recriar o design do Qlik Cloud do zero, as extensões clonam o wrapper MUI do botão Bookmarks e substituem apenas o botão interno - garantindo compatibilidade visual automática com updates da plataforma:

var bm = document.querySelector('[data-tid="assets-button-bookmarks"]');
var wrap = bm.parentNode.cloneNode(true);    // clone do wrapper MUI
var freshBtn = wrap.querySelector('button').cloneNode(false);
freshBtn.innerHTML = QORE_ICON_16;
freshBtn.addEventListener('click', onOpen);
bm.parentNode.insertBefore(wrap, bm.nextSibling);

3. applyPatches, nunca setProperties para hypercubes

Usar setProperties para modificar dimensões e medidas de um hypercube pode desincronizar o qInterColumnSortOrder com o novo array - o Engine emite "Invalid sort order" e outros objetos da sheet quebram. A solução: applyPatches com normalização explícita da ordem de sort após cada mutação.

⚠️
Limite de 10.000 células: O Qlik Cloud limita 10.000 células por request de getData. Para uma tabela com 20 colunas, isso significa no máximo 500 linhas por chamada. A Qore Straight Table calcula safePageSize = floor(10000 / totalCols) e faz múltiplas chamadas quando necessário - transparente para o usuário.
Seção 07 - O Ponto Central

Extensões não são workarounds. São a plataforma.

Existe uma crença de que customizar uma ferramenta de BI com extensões é sinal de limitação da ferramenta. A perspectiva correta é oposta: o Qlik Cloud foi projetado para ser extensível. A Engine API, o sistema de propriedades, o suporte a RequireJS AMD - tudo isso é infraestrutura de primeira classe para construir exatamente o que a empresa precisa.

O que o Qore Extension Framework demonstra é que é possível construir extensões que:

  • Sobrevivem a updates da plataforma (MUI clone, seletores robustos)
  • Escalam para centenas de usuários simultâneos (singleton, Engine API correta)
  • Se integram com sistemas externos sem criar dependências frágeis (cube-driven lookups)
  • Mantêm o mesmo nível de UX do Qlik nativo (toolbar injection, edit-mode gating)
  • Evoluem com segurança (applyPatches, normalização de sort order)

A lacuna entre o que o Qlik entrega out-of-the-box e o que a empresa realmente precisa não é um problema. É uma oportunidade de construir valor diferenciado - diretamente na plataforma onde as decisões acontecem.
