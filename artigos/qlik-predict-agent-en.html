Qlik Predict Agent: What AutoML with AI Actually Means for Senior Devs Who Already Use Python and Qlik

In June 2026, Qlik launched the Predict Agent: an AI agent that runs the full machine learning lifecycle inside Qlik Cloud, with per-record SHAP explainability and continuous model learning. The question no article has answered yet: when does this replace your external Python pipeline, and when should you keep it exactly where it is.

This Is Not Just Rebranded AutoML

Qlik Predict has existed since the Qlik AutoML era. What changed in June 2026 was the addition of an AI agent layer on top of that engine. The practical difference matters for anyone who has used the previous AutoML product.

With plain AutoML, you configured an experiment manually: chose the target variable, selected features, kicked off training, and interpreted the output charts. It was faster than writing code, but it still required you to know what you were asking and understand what came back.

With the Predict Agent, you ask a question in natural language: "Which customers are most likely to churn in the next 30 days?" The agent understands the problem, identifies relevant features, trains multiple models, compares accuracy across them, generates predictions, and explains the results with SHAP visualizations. The complete cycle happens inside a conversation.

Technical note
The underlying ML engine has not changed. What the agent adds is: (1) translation of natural language questions into experiment configurations, (2) automatic decisions on feature selection and problem type classification, (3) a result interpretation narrative that does not require the user to read a SHAP chart on their own.

What is available in GA

Multivariate time series forecasting with support for seasonality and complex inter-variable dependencies. SHAP values at individual record level: not just "which features matter for the model overall," but "why this specific customer received this score." Continuous learning, where models automatically update as new data arrives. Governance with built-in documentation, audit logs, and model lifecycle tracking.

Per-record SHAP: what changes in practice
Most AutoML tools show global feature importance, something like "purchase recency contributes 28% to the model." The Predict Agent shows why that specific record received that specific score. For an analyst presenting a churn prediction to an account manager, this changes the entire conversation: from "the model says the probability is 87%" to "this customer is at risk because order volume dropped 40% over the last 60 days and average ticket is 35% below their historical baseline." The stakeholder understands without needing ML training.

Predict Agent vs. External Python: When to Use Each

This is the decision that will have the most impact on senior devs who already have ML pipelines running outside Qlik. The honest answer: it depends on the scenario. The two approaches coexist, and there is no reason to migrate everything to the agent just because it exists.

Practical rule
If the data is already in Qlik, the problem is standard classification or regression, and the result needs to surface in the app for a business user, the Predict Agent gets you there faster. If the problem requires heavy feature engineering, integration with data outside Qlik, or granular control over the model artifact, external Python is still the right choice.

How It Works in Practice: From Question to Prediction in Your App

A concrete example using retail data. You have CustomersFact and OrdersFact in your Data Product in Qlik Cloud. You open the Predict Agent and describe what you need: 

-- Predict Agent prompt
"Using CustomersFact and OrdersFact, I want to predict which
 customers have more than a 70% probability of making no purchases
 in the next 60 days.

 Include an explanation of why each customer is at risk,
 using the variables available in the data."

The agent runs the complete sequence autonomously:

1. Problem understanding: classifies this as a binary classification problem (churned in the next 60 days: yes or no). Defines the target variable and the prediction horizon based on the description.

2. Feature selection: analyzes available columns and suggests the most relevant ones: days since last purchase, order frequency over the last 90 days, change in average order value, number of distinct categories purchased, customer tenure.

3. Training and validation: trains multiple algorithms, compares AUC-ROC and F1-score across them, selects the best-performing model on the validation set, and surfaces the metrics for your review.

4. Prediction generation: applies the model to all active customers and generates a churn probability score per record.

5. Individual SHAP explanation: for each customer above the 70% probability threshold, generates individual SHAP values with the positive or negative contribution of each feature to that specific record's score.

The final output appears as a table in your Qlik app with a score per customer, accompanied by a SHAP chart that the account manager can interpret without any machine learning training.

What used to take weeks
This workflow, built with external Python and manually integrated into Qlik, used to take two to four weeks of engineering: data collection, feature engineering pipeline, training, model versioning, inference API, Qlik connector, and refresh scheduling. With the Predict Agent, the delivery moves to the same afternoon, as long as the data is already in the Data Product with the necessary quality.

The Combination Nobody Is Talking About: Predict + Automate Agent

Qlik launched the Automate Agent in the same June 2026 window. When combined with the Predict Agent, it closes a loop that previously required multiple external systems and manual integration between them.

Predict Agent

Detects and predicts: identifies at-risk customers, forecasts margin compression, anticipates supply chain bottlenecks. Returns a score with individual explanation per record.

Automate Agent

Acts on the prediction: uses the Predict Agent result to trigger actions in external systems via natural language. CRM, ERP, procurement systems, communication platforms.

Analytics Agent

Investigates causes: answers analytical questions about the data, explores variations, and supports both insight generation and analytics development tasks inside Qlik Cloud.

The example Qlik itself uses is supply chain: the Predict Agent identifies an 82% probability of a stockout on a critical SKU in the next 14 days. The Automate Agent, without human intervention, automatically opens a procurement workflow in the purchasing system to identify an alternative supplier.

For BI teams that today deliver monitoring dashboards, this represents a paradigm shift: from "the dashboard alerts that there is a problem" to "the system acts on the problem before it shows up in the morning report."

For the senior dev: what this changes in system design
If you are building a Qlik app that serves as a KPI monitoring panel, it is worth mapping which KPIs have an associated action when they fall outside the expected threshold. Those are the natural candidates for the Predict + Automate loop. The action logic moves out of your manual pipeline and into the agent, but the data contract feeding the model remains the engineer's responsibility.

What Stays in the Senior Dev's Hands

The Predict Agent does not eliminate the engineer's technical responsibility. It shifts it. Understanding exactly what migrates to the agent and what remains with you is what separates successful adoption from rework.

Agent handles

  • Automatic algorithm selection
  • Hyperparameter tuning
  • Cross-validation and best-model selection
  • SHAP values and explanation narrative
  • Automatic model updates as new data arrives
  • Experiment documentation and audit logging
  • Result integration into the Qlik app

You remain responsible for

  • Data quality and granularity in the Data Product
  • Domain-specific feature engineering
  • Correctly defining the problem and target variable
  • Models with strict regulatory requirements
  • ML architectures beyond classification and regression
  • Integration with data sources outside Qlik
  • Access governance on results via Section Access

The critical point that marketing glosses over: the Predict Agent is only as good as the data flowing into it. If the input Data Product has quality issues, high latency, or insufficient granularity, the agent will generate a technically valid model that is practically useless to the business. Responsibility for the data layer stays with the engineer, and the weeks saved on the ML side can be consumed entirely by technical debt in the ingestion and transformation layer.
