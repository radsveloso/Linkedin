GA Announcement

Qlik announced the general availability of agentic data engineering capabilities across Qlik Cloud on June 30, 2026, moving capabilities introduced at Qlik Connect 2026 into production. Available now in Qlik Talend Cloud and Qlik Cloud Analytics.

What Qlik actually means by "agentic"

Before diving into code, let's align on vocabulary. Qlik did not ship a data chatbot with access to your app. They shipped four specialized agents, each with a defined scope, available via conversational interface and via MCP (Model Context Protocol).

The distinction matters: a chatbot answers questions. An agent executes tasks, maintains context across steps, and can be orchestrated by other systems. That is the shift that changes your daily workflow as a senior developer.

Declarative Pipelines: the biggest shift for engineers

This is the capability that most directly impacts engineers who work daily with Load Script. Understanding the conceptual difference first will help you decide when to use it and when to stay with what you know.

The traditional Load Script is imperative: you specify step by step how to transform and load each table. Declarative pipelines are a contract: you define what should exist, and the system decides how to generate, optimize, and maintain it.

Before: Imperative Load Script
  • You write every step
  • Load order affects associations
  • Schema changes require manual rewrites
  • Documentation lives separately from code
  • Hard to version as a stable contract
After: Declarative Pipeline
  • You define the intent
  • Stable, versionable contract
  • Agent generates and refactors automatically
  • Documentation embedded in the spec
  • Compatible with external coding agents
Technical note

Load Script has not been deprecated. Declarative pipelines coexist with existing scripts. Complex business logic, the Qlik associative model, and advanced Set Analysis transformations remain your responsibility. What the agent takes over is the generation and maintenance of standard ingestion and transformation boilerplate.

Example: traditional ingestion vs. declarative

A common scenario: loading orders from a QVD with date formatting and a filter on year.

QVS · Load Script (imperative mode) OrdersFact.qvs 
// Traditional approach: you write every line
OrdersFact:
LOAD
    OrderID,
    CustomerID,
    Date(OrderDate, 'YYYY-MM-DD') as OrderDate,
    Num(TotalAmount, '#,##0.00') as TotalAmount,
    ProductID,
    StatusCode
FROM [lib://DataLake/orders.qvd] (qvd)
WHERE Year(OrderDate) >= 2024;

// Problem: any schema change requires a manual rewrite
// No documentation of intent, only of execution
Prompt to the Pipeline Agent via chat or MCP 
// You describe the intent; the agent generates the declarative spec
// and the optimized script from it

"Create a pipeline for the OrdersFact table with these rules:
 - Source: QVD at lib://DataLake/orders.qvd
 - Format OrderDate as YYYY-MM-DD
 - Format TotalAmount as USD currency
 - Filter records from 2024 onwards only
 - CustomerID is a join key with CustomersDim
 - Freshness SLO: data available by 06:00 AM EST daily"

// Result: versionable spec + generated script + quality rule
// When source schema changes, agent refactors the script
// while preserving the contract

MCP Integration: Qlik with Claude Code or GitHub Copilot

This is the part that will resonate most with developers who already use AI in their daily coding workflow. Qlik shipped MCP tools that let you configure any compatible coding agent, including Claude Code and GitHub Copilot, to interact directly with Qlik Cloud.

The practical implication: you can use the coding agent already approved by your organization to build pipelines, manage Data Products, and query the Qlik catalog without switching interfaces.

JSON · MCP Configuration claude_desktop_config.json 
{
  "mcpServers": {
    "qlik-cloud": {
      "command": "npx",
      "args": ["@qlik/mcp-server"],
      "env": {
        "QLIK_HOST": "your-tenant.us.qlikcloud.com",
        "QLIK_CLIENT_ID": "your-oauth-client-id",
        "QLIK_CLIENT_SECRET": "your-client-secret"
      }
    }
  }
}

With the configuration in place, you can prompt your coding agent directly from your editor:

Prompt examples via MCP 
// Quality audit
"List all Data Products with a trust score below 80%"

// Quality rule creation
"Create a quality rule to ensure OrderDate is never null
 in the OrdersFact table"

// Pipeline generation
"Generate the declarative pipeline to load the Customers table
 from Snowflake into the Qlik DataLake, with a 4-hour freshness SLO
 and automatic duplicate detection"

// Catalog exploration
"Which tables in the catalog contain financial transaction data
 and have incomplete glossary documentation?"
What this means in practice

The workflow changes from: open Qlik Hub, navigate to Data Integration, create pipeline manually, switch back to your editor to integrate. To: describe what you need in your editor and receive the generated pipeline with SLO and documentation already attached. The change is in context-switching cost, not in technical capability.

Data Quality with SLOs: giving your data a service contract

The SLO (Service Level Objective) concept comes from software engineering (SRE) and Qlik has brought it to data. Instead of manual, periodic quality checks, you define quality contracts that are monitored continuously.

The Data Quality Agent lets you create these contracts via natural language, and the resulting trust scores surface directly inside Qlik apps for end users to see when analyzing data.

Example: SLO via agent 
// Defining an SLO for the OrdersFact table
"Define an SLO for OrdersFact with the following criteria:
 - OrderDate completeness: >= 99.5%
 - OrderID uniqueness: 100%
 - Freshness: today's data available by 06:00 AM EST
 - TotalAmount must not be negative: 100%
 - CustomerID must exist in CustomersDim: >= 99%"

// The agent:
// 1. Creates quality rules for each criterion
// 2. Schedules automatic verification
// 3. Calculates the composite trust score
// 4. Configures alerts when SLO is violated
// 5. Surfaces the trust score inside Qlik apps

Why this matters for senior devs

Previously, a trust score was a number you invented or calculated manually in a dashboard. Now it is an auditable contract, with a violation history, a responsible owner, and visibility into which SLO dimension failed. The user who reads a chart also sees the confidence level of the data they are analyzing.

For teams serving regulated industries (financial services, healthcare, compliance), this stops being a differentiator and becomes a baseline expectation within the next 12 to 24 months.

The point nobody talks about

Every time a platform ships AI for data engineering, the conversation drifts to "will engineers be replaced?" That is not the right question.

What agents take over vs. what stays your responsibility

Agents absorb

  • Standard ingestion boilerplate
  • Asset cataloging and documentation
  • Repetitive quality rule creation
  • Pipeline anomaly detection
  • Generating declarative specifications
  • Refactoring when source schema changes

You remain responsible for

  • The Qlik associative data model design
  • Complex business logic in scripts
  • Set Analysis for domain-specific metrics
  • QVD layer strategy and incremental loads
  • Section Access and data governance
  • Domain knowledge and business context

A senior developer who already understands the Qlik associative engine becomes more productive with agents. A developer who does not understand it will create problems faster, because the agent will generate code without the context of how Qlik associates data in memory.

The learning curve has not disappeared. It has shifted: from "how to write the script" to "how to specify well what the agent should generate."

Practical recommendation

If you already have Qlik Talend Cloud or Qlik Cloud Analytics Enterprise, start with the Data Quality Agent. It delivers the fastest ROI: trust scores start appearing in your apps within days, and business users notice the difference immediately. Declarative pipelines require more upfront work on specification to produce consistent results at scale.

What senior devs should do next

A practical roadmap for staying ahead of the curve over the next six months:

1. Configure the Qlik MCP server in your coding agent. Available now, no license change required if you are already on Qlik Cloud Analytics. This is the fastest entry point with the lowest setup cost.

2. Map which ingestion pipelines are declarative candidates. Simple ingestion from structured sources, without heavy business logic, are the best candidates. Scripts with complex business transformations remain manual code for now.

3. Define your first SLOs for the three most critical tables. Pick the tables your business uses most and write explicit quality contracts. This creates auditable evidence and gives business users real-time data confidence visibility.
