01 — Diagnóstico

O app funciona.
Mas por quanto tempo?

A maioria dos ambientes Qlik Sense que encontro em empresas passa no teste visual: dashboards bonitos, dados aparentemente corretos, usuários navegando. Mas quando você olha por baixo do capô, a história é diferente.

Scripts sem camada QVD. Reloads que extraem 100% dos dados da fonte toda vez. Joins desnecessários no front-end. Section Access mal configurado. São apps que funcionam até o dia que não funcionam mais — e quando caem, ninguém sabe por onde começar.

02 — Arquitetura

As 3 camadas que
separam amadores de sêniors

Ambientes Qlik de produção sérios seguem uma arquitetura de camadas QVD. É o equivalente ao modelo Medallion (Bronze/Silver/Gold) que o mundo do Data Engineering adotou — mas aplicado ao ecossistema Qlik.

🥉RAW
QVD

Camada 1 — Extração Bruta

Cópia exata da fonte. Sem transformação. Sem join. Sem filtro. É o seu backup histórico e ponto de verdade. Nunca conecte um app diretamente aqui.

🥈TRANSFORM
QVD

Camada 2 — Transformação

Limpeza, tipagem, enriquecimento e join entre entidades. É aqui que a lógica de negócio vive. Scripts modulares, um arquivo por entidade.

🥇APP
QVD

Camada 3 — App de Consumo

Lê apenas QVDs transformados. Script enxuto, sem lógica de negócio. Aggregations e filtros de Section Access. Reload em minutos, não horas.

01_RAW_Orders.qvs — Camada de Extração 
// ═══════════════════════════════════════════
// CAMADA RAW — Extração pura da fonte
// Sem transformação. Sem join. Sem filtro.
// ═══════════════════════════════════════════

LET vQVDRaw   = 'lib://QVD/Raw/';
LET vQVDTF    = 'lib://QVD/Transform/';

Orders_RAW:
LOAD
    OrderID,
    CustomerID,
    OrderDate,
    Amount,
    Status,
    Now() AS _ExtractedAt
FROM [lib://DataSources/ERP_Orders.csv]
(txt, delimiter is ',', embedded labels);

STORE Orders_RAW INTO [$(vQVDRaw)Orders_RAW.qvd] (QVD);
DROP TABLE Orders_RAW;
03 — Performance

Incremental Load —
fim do full extract

Se seu script extrai 100% dos dados da fonte a cada reload, você está desperdiçando recursos, aumentando a janela de falha e colocando pressão desnecessária nos sistemas transacionais. O Incremental Load resolve isso carregando apenas os registros novos ou modificados.

02_TF_Orders.qvs — Incremental Load com QVD 
// ═══════════════════════════════════════════
// INCREMENTAL LOAD — Carrega só o delta
// Compara data de criação do QVD com a fonte
// ═══════════════════════════════════════════

// Pega o timestamp do último reload
IF NOT IsNull(QVDCreateTime('$(vQVDTF)Orders_TF.qvd')) THEN
    LET vLastLoad = QVDCreateTime('$(vQVDTF)Orders_TF.qvd');
ELSE
    LET vLastLoad = '1900-01-01'; // Primeiro reload: carga completa
END IF

// Carrega registros existentes do QVD
Orders_TF:
LOAD *
FROM [$(vQVDTF)Orders_TF.qvd] (qvd)
WHERE OrderID NOT IN (
    SELECT OrderID FROM Orders WHERE ModifiedAt >= '$(vLastLoad)'
);

// Concatena apenas o delta da fonte
CONCATENATE (Orders_TF)
SQL SELECT
    OrderID,
    CustomerID,
    CAST(OrderDate AS DATE) AS OrderDate,
    Amount,
    UPPER(TRIM(Status))        AS Status
FROM dbo.Orders
WHERE ModifiedAt >= '$(vLastLoad)';

STORE Orders_TF INTO [$(vQVDTF)Orders_TF.qvd] (QVD);
DROP TABLE Orders_TF;
03_APP_Dashboard.qvs — Section Access granular 
// ═══════════════════════════════════════════
// SECTION ACCESS — Segurança por linha de dado
// Nunca deixe isso no app sem testar em staging
// ═══════════════════════════════════════════

Section Access;
Access_Control:
LOAD * INLINE [
    ACCESS,   USERID,          REGION,    OMIT
    ADMIN,    DOMAIN\RAFAEL,   *,
    USER,     DOMAIN\ANA,      Sul,       Amount
    USER,     DOMAIN\CARLOS,   Norte,     Amount
    USER,     DOMAIN\LUCIA,    Sudeste,
];

Section Application;

// Carrega apenas QVDs transformados
Orders:
LOAD
    OrderID,
    CustomerID,
    OrderDate,
    Year(OrderDate)           AS [Ano],
    Month(OrderDate)          AS [Mês],
    Amount,
    Status,
    Region                     // Campo de controle do Section Access
FROM [$(vQVDTF)Orders_TF.qvd] (qvd);
04 — Erros Fatais

Os 5 erros que derrubam
qualquer ambiente Qlik

Não importa o tamanho da empresa ou o quanto foi investido em licenças — esses erros aparecem em todos os lugares e são todos evitáveis.

1

Chaves sintéticas não tratadas

Quando duas tabelas compartilham mais de um campo em comum, o Qlik cria chaves sintéticas automaticamente. Elas degradam performance e tornam o modelo imprevisível. Solução: renomear campos ou usar composite keys explícitas.

2

Full extract em tabelas de milhões de linhas

Extrair 50 milhões de pedidos todas as noites quando apenas 0,1% mudou é desperdício puro. Implemente Incremental Load com campo de controle (ModifiedAt, RowVersion) e reduza o reload em até 95%.

3

Lógica de negócio no front-end

KPIs calculados em Set Analysis complexo que deveriam estar no script como campos calculados. Isso multiplica o processamento por cada objeto do dashboard. Calcule no script, exponha como campo.

4

Section Access sem staging

Section Access mal configurado em produção pode bloquear todos os usuários instantaneamente — incluindo administradores. Sempre teste em ambiente de desenvolvimento com usuários reais antes de promover.

5

Scripts monolíticos sem modularização

Um script de 3.000 linhas que faz tudo: extração, transformação, joins e carga. Impossível de debugar, impossível de manter. Divida em arquivos por entidade e use variáveis globais de configuração.

05 — Checklist

Seu app está pronto
para produção?

Antes de promover qualquer app para produção, passe por este checklist. Se algum item falhar, você tem trabalho a fazer.

  • ✓
    Arquitetura QVD em camadasRAW → Transform → App. Nenhum app conecta diretamente na fonte de dados.
  • ✓
    Incremental Load implementadoReload carrega apenas delta. Tempo de reload documentado e monitorado.
  • ✓
    Zero chaves sintéticas no data modelViewer do data model sem nenhuma chave sintética (tabelas pontilhadas).
  • ✓
    Section Access testado em stagingCada perfil de usuário validado com usuários reais antes de produção.
  • ✓
    Scripts modularizados e comentadosUm arquivo por entidade. Variáveis de configuração centralizadas. Qualquer dev consegue dar manutenção.
  • ✓
    Monitoramento de performance ativoQlik Sense App Analyzer ou Operations Monitor configurado. Alertas de falha de reload ativos.
  • ✓
    Documentação do data modelDicionário de dados com definição de cada campo e tabela. Atualizado a cada mudança.
